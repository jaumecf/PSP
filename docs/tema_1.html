Tema 1: Programació Multiprocés

1. Conceptes Bàsics de Processos

En els sistemes operatius moderns, és fonamental diferenciar entre tres conceptes clau relacionats amb l'execució de codi:

  • Programa: Element estàtic. Conjunt d'instruccions en un llenguatge de programació emmagatzemat en disc que defineix la lògica de l'aplicació.
  • Executable: Fitxer en format binari preparat pel SO per ser carregat en memòria.
  • Procés: Element dinàmic. Instància d'un programa en execució amb recursos assignats de manera independent (espai d'adreçament de memòria, registres de CPU, comptador de programa i taula de descriptors de fitxers).
Exemple pràctic: Si s'obre tres vegades l'executable d'un navegador web, el sistema operatiu crea 3 processos independents, cadascun amb el seu propi PID i espai de memòria aïllat.

Bloc de Control de Procés (PCB) i Aïllament

El sistema operatiu manté el control de cada procés mitjançant una estructura de dades anomenada PCB (Process Control Block), que conté:

  • PID (Process Identifier): Identificador únic del procés.
  • Estat del procés (Llest, En execució, Bloquejat, etc.).
  • Comptador de programa (PC) i registres del processador.
  • Informació de gestió de memòria i prioritat de la CPU.

Per motius de seguretat i estabilitat, un procés no pot llegir ni escriure directament en la memòria reservada per a un altre procés sense mecanismes d'IPC (Inter-Process Communication).

2. Gestió de Processos en el Sistema Operatiu

Quan un procés en execució sol·licita la creació d'un nou procés, es forma una jerarquia pare-fill coneguda com a Arbre de Processos.

Tipologia de Processos segons la Interfície

  • Primer Pla (Foreground): Processos que requereixen la interacció directa amb l'usuari mitjançant interfície gràfica (GUI) o consola (CLI).
  • Segon Pla (Background) / Dimonis (Daemons): Processos que s'executen en segon pla sense interfície d'usuari directament visible (ex: servidors de base de dades com MySQL o servidors HTTP).

3. Cicle de Vida d'un Procés

Un procés passa per diferents estats des de la seva creació fins a la seva finalització:

  • Nou (New): El procés s'està creant i reservant memòria.
  • Llest (Ready): Esperant que el programador de la CPU (Scheduler) li assigni temps d'execució.
  • En Execució (Running): Les instruccions del procés s'estan executant a la CPU.
  • Bloquejat (Waiting / Blocked): El procés no pot continuar fins que es produeixi un esdeveniment extern (com una operació d'E/S en disc o xarxa).
  • Finalitzat (Terminated): El procés ha acabat l'execució i el SO n'allibera els recursos.

4. Concurrència vs. Paral·lelisme

És indispensable distingir entre ambdós modalitats d'execució:

  • Programació Concurrent: Múltiples tasques progressen en intervals de temps intercalats. En un sistema d'un sol nucli, s'aconsegueix mitjançant el canvi ràpid de context (multiprogramació).
  • Programació Paral·lela: Múltiples instruccions s'executen simultàniament en el mateix instant de temps aprofitant diferents nuclis (multicore) o processadors físics.

5. Comparativa: Processos vs. Fils (Threads)

A continuació es detallen les diferències estructurals principals entre processos i fils:

Característica Procés (Pesat) Fil / Thread (Lleuger)
Espai de Memòria Aïllat i independent per a cada procés. Compartit entre tots els fils del mateix procés.
Cost de Creació Elevat sobrecapçalera (overhead) per al SO. Molt baix i ràpid de crear.
Canvi de Context Lent, requereix guardar l'estat complet del PCB. Ràpid, només requereix canviar el registre i pila.
Comunicació Requereix mecanismes d'IPC (Pipes, Sockets, etc.). Directa mitjançant variables compartides en memòria.

6. Canals d'E/S Estàndard i la Perspectiva de Java

Tot procés creat pel sistema operatiu disposa de 3 canals d'E/S per defecte:

  • stdin (FD 0): Entrada estàndard (normalment el teclat).
  • stdout (FD 1): Sortida estàndard (normalment la pantalla).
  • stderr (FD 2): Sortida d'errors estàndard.
Punt clau en Java: Els mètodes de la classe Process estan dissenyats des de la perspectiva del Programa Pare. Per tant, getInputStream() llegeix el que el fill escriu a la seva sortida estàndard, i getOutputStream() permet escriure dades cap a l'entrada estàndard del fill. 
// Configuració i execució d'un procés fill en Java
ProcessBuilder pb = new ProcessBuilder("java", "ProcessFill");
Process p = pb.start();

// Enviar dades CAP AL procés fill (connecta a la stdin del fill)
OutputStream out = p.getOutputStream();

// Llegir la sortida QUE PRODUEIX el procés fill (connecta a la stdout del fill)
InputStream in = p.getInputStream();

// Capturar els errors generats pel fill (connecta a la stderr del fill)
InputStream err = p.getErrorStream();

7. Gestió Avançada de Fluxos i Prevenció de Deadlocks

La comunicació entre el procés pare i el fill es realitza mitjançant buffers de memòria intermediària gestionats pel sistema operatiu.

Risc de Buffer Deadlock: Si un procés fill generi un volum gran de dades per stdout o stderr i el pare no les llegeix de forma paral·lela, el buffer de memòria s'omplirà i el fill es bloquejarà. Si el pare executa waitFor() abans de buidar els fluxos, tots dos processos quedaran bloquejats indefinidament.

Bones Pràctiques en Java

  1. Unificar els fluxos de sortida i d'errors per facilitar la lectura: 
    pb.redirectErrorStream(true);
  2. Redirigir directament la sortida a la consola del pare si no cal processar-la programàticament: 
    pb.redirectOutput(ProcessBuilder.Redirect.INHERIT);
  3. Forçar sempre l'enviament de dades pendents amb out.flush() i tancar el flux amb out.close() en finalitzar l'escriptura cap al fill.

8. Resum de l'API de Java (`java.lang`)

Per a la gestió multiprocés en Java s'utilitzen principalment dues classes indispensables:

  • ProcessBuilder: Permet configurar l'ordre a executar, el directori de treball, les variables d'entorn i la redirecció de fluxos abans d'iniciar el procés.
  • Process: Representa la instància d'un procés en execució generat per ProcessBuilder.start(). Permet sincronitzar l'execució (waitFor()), finalitzar el procés (destroy()) i gestionar-ne les E/S.
