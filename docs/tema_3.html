1.1. Èmfasi en la Capa de Transport: TCP vs. UDP

La capa d'Internet (IP) només sap portar paquets d'un ordinador A a un ordinador B. És la Capa de Transport la que permet que múltiples aplicacions d'un mateix ordinador (el navegador, Spotify, el nostre servidor Java) es comuniquin simultàniament sense barrejar dades. Per fer-ho, ens ofereix dos grans protocols:

  • TCP (Transmission Control Protocol): Protocol orientat a connexió. Abans d'enviar dades, estableix un canal virtual (Three-Way Handshake: SYN, SYN-ACK, ACK). Garanteix que tots els bytes arriben, sense errors i en el mateix ordre en què es van enviar. Si un paquet es perd, TCP el reenvia automàticament.
  • UDP (User Datagram Protocol): Protocol sense connexió. Envia paquets independents (datagrames) directament a la xarxa sense preguntar si el receptor està preparat. No garanteix l'entrega ni l'ordre, però no té sobrecàrrega de control i és extremadament ràpid.
Característica TCP (Flux de Bytes) UDP (Datagrames)
Connexió Orientat a connexió (canal establert abans de parlar). Sense connexió (enviament directe paquet a paquet).
Fiabilitat Alta. Garanteix l'entrega mitjançant confirmacions (ACK). Baixa ("Best-effort"). Un paquet es pot perdre sense avís.
Ordre d'arribada Garantit. El receptor reconstrueix el flux en ordre exacte. No garantit. Poden arribar desordenats o duplicats.
Velocitat i Latència Més lent (capçaleres de 20 bytes + control de flux/congestió). Molt ràpid i lleuger (capçalera mínima de només 8 bytes).
Classes en Java ServerSocket i Socket DatagramSocket i DatagramPacket
Casos d'ús típics Web (HTTP), transferència d'arxius, correu, xats, banca. Streaming de vídeo/àudio, jocs multijugador, DNS, VoIP.

Bloc 2: Fonaments dels Sockets, Adreces IP i Ports

Un Socket (endoll) és la interfície de programació que connecta la capa d'aplicació (el nostre codi Java) amb la capa de transport del Sistema Operatiu. Un socket queda identificat de manera única a tot el món per la combinació de:

Identificació d'un extrem de comunicació:
Socket = Adreça IP + Port + Protocol de Transport (TCP o UDP)
  • Adreça IP (java.net.InetAddress): Identifica el dispositiu dins la xarxa. L'adreça especial 127.0.0.1 (o localhost) apunta sempre a la pròpia màquina (interfície de loopback), ideal per provar client i servidor al mateix PC.
  • Port (0 a 65.535): Número enter de 16 bits que identifica l'aplicació concreta dins del dispositiu:
    • 0 – 1023: Ports ben coneguts (reservats pel sistema: 80 HTTP, 443 HTTPS, 22 SSH, 53 DNS).
    • 1024 – 49151: Ports registrats (on solem ubicar els nostres servidors de pràctiques, ex: 5000, 8080).
    • 49152 – 65535: Ports dinàmics o efímers (assignats automàticament pel SO als clients quan obren una connexió).

3.1. Gestió de Fluxos (Streams) en TCP

Un cop connectats, tant el client com el servidor disposen d'un objecte Socket. Aquest objecte proporciona dos canals de bytes en cru: getInputStream() i getOutputStream(). Com que treballar amb arrays de bytes és incòmode, els embolcallem amb classes de java.io:

  • Per enviar text línia a línia: BufferedReader (lectura amb readLine()) i PrintWriter (escriptura amb println()).
  • Per enviar dades primitives tipificades (int, double, boolean, UTF): DataInputStream i DataOutputStream.
Atenció al buffer de sortida (autoFlush):
Quan creïs un PrintWriter sobre un socket, passa sempre true com a segon paràmetre: new PrintWriter(socket.getOutputStream(), true). Si no ho fas, les dades es quedaran retingudes a la memòria intermèdia i el receptor es quedarà bloquejat esperant al readLine().

3.2. Exemple 1: Servidor i Client Eco TCP (Monofil)

ServidorEcoTCP.java

import java.io.*;
import java.net.*;

public class ServidorEcoTCP {
    public static void main(String[] args) {
        final int PORT = 5000;

        try (ServerSocket servidor = new ServerSocket(PORT)) {
            System.out.println("Servidor TCP escoltant al port " + PORT + "...");

            // accept() bloqueja l'execució fins que entra un client
            try (Socket clientSocket = servidor.accept();
                 BufferedReader entrada = new BufferedReader(
                         new InputStreamReader(clientSocket.getInputStream()));
                 PrintWriter sortida = new PrintWriter(
                         clientSocket.getOutputStream(), true)) {

                System.out.println("Client connectat des de: " + clientSocket.getInetAddress());

                String missatge;
                while ((missatge = entrada.readLine()) != null) {
                    System.out.println("Rebut: " + missatge);
                    if ("ADEU".equalsIgnoreCase(missatge)) {
                        sortida.println("Connexió tancada pel servidor.");
                        break;
                    }
                    sortida.println("ECO: " + missatge.toUpperCase());
                }
            }
        } catch (IOException e) {
            System.err.println("Error de xarxa al servidor: " + e.getMessage());
        }
    }
}

ClientEcoTCP.java

import java.io.*;
import java.net.*;
import java.util.Scanner;

public class ClientEcoTCP {
    public static void main(String[] args) {
        final String HOST = "127.0.0.1";
        final int PORT = 5000;

        try (Socket socket = new Socket(HOST, PORT);
             BufferedReader entrada = new BufferedReader(
                     new InputStreamReader(socket.getInputStream()));
             PrintWriter sortida = new PrintWriter(
                     socket.getOutputStream(), true);
             Scanner teclat = new Scanner(System.in)) {

            System.out.println("Connectat al servidor. Escriu missatges (ADEU per sortir):");
            String text;
            do {
                System.out.print("> ");
                text = teclat.nextLine();
                sortida.println(text); // Envia al servidor
                String resposta = entrada.readLine(); // Espera resposta
                System.out.println("Servidor respon: " + resposta);
            } while (!"ADEU".equalsIgnoreCase(text));

        } catch (IOException e) {
            System.err.println("No s'ha pogut connectar al servidor: " + e.getMessage());
        }
    }
}

Bloc 4: Sockets UDP en Java (Sense Connexió)

En UDP no existeix el concepte de client connectat ni de fluxos (InputStream/OutputStream). La comunicació funciona com el correu postal tradicional:

  • DatagramSocket: És la bústia per on s'envien i es reben paquets.
  • DatagramPacket: És el sobre. Quan enviem, hi posem les dades (byte[]), la longitud, l'adreça IP de destí i el port de destí. Quan rebem, preparem un sobre buit (un buffer) i el mètode receive() l'omple i anota al mateix sobre qui ha estat el remitent (packet.getAddress() i packet.getPort()).

4.1. Exemple 2: Servidor i Client de Consulta Ràpida UDP

ServidorUDP.java

import java.net.*;
import java.time.LocalTime;

public class ServidorUDP {
    public static void main(String[] args) {
        final int PORT = 6000;

        try (DatagramSocket socket = new DatagramSocket(PORT)) {
            System.out.println("Servidor UDP actiu al port " + PORT);
            byte[] bufferRecepcio = new byte[1024];

            while (true) {
                // 1. Preparem el paquet buit per rebre dades
                DatagramPacket paquetRebut = new DatagramPacket(bufferRecepcio, bufferRecepcio.length);
                socket.receive(paquetRebut); // Bloquejant fins que arriba un datagrama

                // Important: utilitzar paquetRebut.getLength() per no llegir bytes residuals!
                String peticio = new String(paquetRebut.getData(), 0, paquetRebut.getLength());
                System.out.println("Petició UDP de " + paquetRebut.getAddress() + ": " + peticio);

                // 2. Preparem la resposta adreçada al remitent del paquet rebut
                String textResposta = "Hora del servidor: " + LocalTime.now();
                byte[] dadesResposta = textResposta.getBytes();

                DatagramPacket paquetEnviament = new DatagramPacket(
                        dadesResposta,
                        dadesResposta.length,
                        paquetRebut.getAddress(),
                        paquetRebut.getPort()
                );
                socket.send(paquetEnviament);
            }
        } catch (Exception e) {
            System.err.println("Error UDP: " + e.getMessage());
        }
    }
}

ClientUDP.java

import java.net.*;

public class ClientUDP {
    public static void main(String[] args) {
        try (DatagramSocket socket = new DatagramSocket()) {
            // Establim un temps màxim d'espera de 3 segons (en UDP la resposta es pot perdre!)
            socket.setSoTimeout(3000);

            InetAddress ipServidor = InetAddress.getByName("127.0.0.1");
            byte[] missatge = "HORA?".getBytes();

            DatagramPacket paquetEnviament = new DatagramPacket(missatge, missatge.length, ipServidor, 6000);
            socket.send(paquetEnviament);

            byte[] bufferResposta = new byte[1024];
            DatagramPacket paquetResposta = new DatagramPacket(bufferResposta, bufferResposta.length);
            socket.receive(paquetResposta);

            String resposta = new String(paquetResposta.getData(), 0, paquetResposta.getLength());
            System.out.println("Resposta rebuda: " + resposta);

        } catch (SocketTimeoutException e) {
            System.err.println("Temps esgotat: el paquet UDP s'ha perdut o el servidor no respon.");
        } catch (Exception e) {
            System.err.println("Error al client UDP: " + e.getMessage());
        }
    }
}

Bloc 5: Servidors Concurrents (Multifil) i Protocols d'Aplicació

L'exemple TCP de la secció 3 té un defecte greu per a un entorn real: és seqüencial. Mentre un client estigui connectat enviant missatges, qualsevol altre client que intenti connectar-se quedarà esperant a la cua del sistema operatiu.

Per resoldre-ho, combinarem els sockets amb els coneixements del Tema 2 (Programació Multifil):

  1. El fil principal del servidor executa un bucle infinit while (true) la única missió del qual és acceptar noves connexions amb serverSocket.accept().
  2. Immediatament després d'acceptar un client, delega el Socket resultant a una tasca Runnable (un worker) executada per un ExecutorService (pool de fils).
  3. Si els diferents fils clients han d'accedir o modificar un recurs comú (com una llista d'usuaris d'un xat o l'estat d'una partida), aquest recurs s'ha de protegir amb synchronized o estructures thread-safe per evitar condicions de carrera (race conditions).

5.1. Exemple 3: Arquitectura de Servidor TCP Multifil amb Pool de Fils

ServidorMultifil.java + GestorClient.java

import java.io.*;
import java.net.*;
import java.util.concurrent.*;

public class ServidorMultifil {
    public static void main(String[] args) {
        final int PORT = 5000;
        // Limitem a 10 clients simultanis per protegir la memòria del servidor
        ExecutorService pool = Executors.newFixedThreadPool(10);

        try (ServerSocket servidor = new ServerSocket(PORT)) {
            System.out.println("Servidor Multifil escoltant al port " + PORT);

            while (true) {
                Socket clientSocket = servidor.accept();
                // Deleguem l'atenció del client a un fil del pool i tornem a escoltar
                pool.execute(new GestorClient(clientSocket));
            }
        } catch (IOException e) {
            System.err.println("Error crític al servidor: " + e.getMessage());
        } finally {
            pool.shutdown();
        }
    }
}

class GestorClient implements Runnable {
    private final Socket socket;

    public GestorClient(Socket socket) {
        this.socket = socket;
    }

    @Override
    public void run() {
        String filNom = Thread.currentThread().getName();
        try (socket;
             BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()));
             PrintWriter out = new PrintWriter(socket.getOutputStream(), true)) {

            out.println("BENVINGUT|Atès pel fil " + filNom);
            String linia;

            // Protocol d'aplicació senzill basat en comandes separades per '|'
            while ((linia = in.readLine()) != null) {
                String[] parts = linia.split("\|", 2);
                String comanda = parts[0].toUpperCase();

                switch (comanda) {
                    case "PING" -> out.println("PONG");
                    case "ECHO" -> out.println(parts.length > 1 ? parts[1] : "ERROR|Falta text");
                    case "EXIT" -> {
                        out.println("BYE");
                        return;
                    }
                    default -> out.println("ERROR|Comanda desconeguda");
                }
            }
        } catch (IOException e) {
            System.out.println("Client desconnectat abruptament (" + filNom + ")");
        }
    }
}

Bloc 6: Errors Habituals i Bones Pràctiques

1. Deadlock d'aplicació (Bloqueig mutu de lectura):
Si el client crida a entrada.readLine() esperant que el servidor li digui alguna cosa, i el servidor també està aturat a entrada.readLine() esperant el client, tots dos programes quedaran congelats indefinidament. Dissenya sempre un protocol clar on se sàpiga qui parla primer i quants missatges s'envien per torn.
2. java.net.BindException: Address already in use:
Passa quan intentes arrencar el servidor en un port (ex: 5000) que ja està ocupat per una execució anterior que no vas aturar a l'IDE (IntelliJ/Eclipse). Atura el procés antic abans de tornar a executar.
3. Ús obligatori de try-with-resources:
Els sockets consumeixen descriptors de fitxer del Sistema Operatiu. Tanca sempre Socket, ServerSocket i els seus fluxos mitjançant blocs try (...) per evitar fuites de recursos.
